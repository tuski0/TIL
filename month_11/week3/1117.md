## 3-1 Retriever 구성과 질의 임베딩

### 질의 임베딩 원리

- 자연어 질문을 임베딩해 벡터 공간의 좌표로 변환한다.
- `embed_query()`는 질문 하나를 벡터로 변환한다. 실습 설정에서는 1,536차원 벡터를 사용한다.

```python
# 사용자 질문을 정의합니다.
user_query = "학부생 도서 대출 권수와 기간을 알려주세요."

# 질문 문장을 벡터(숫자 좌표 배열)로 변환합니다.
query_vector = embeddings_model.embed_query(user_query)

# 생성된 벡터의 차원 수와 샘플 값을 출력합니다.
print(f"질의 텍스트: {user_query}")
print(f"생성된 벡터 차원: {len(query_vector)}차원")
print(f"변환된 좌표 샘플 (앞 5개): {query_vector[:5]}")
```

### Retriever 인터페이스 구성

- Retriever는 자연어 질의를 받아 관련 `Document` 목록을 반환한다.
- `as_retriever()`로 벡터 저장소를 Retriever로 구성하고, `invoke()`로 질의를 실행한다.

```python
# PGVector 저장소를 Retriever 인터페이스로 변환합니다.
retriever = vector_store.as_retriever()

# Retriever를 호출하여 질문과 가장 유사한 문서를 검색합니다.
retrieved_docs = retriever.invoke(user_query)

# 검색된 문서 건수와 가장 연관성 높은 1순위 문서를 확인합니다.
print(f"검색된 문서 건수: {len(retrieved_docs)}건")
print("=== [1순위 검색 문서 본문] ===")
print(retrieved_docs[0].page_content)
print("=== [1순위 검색 문서 메타데이터] ===")
print(retrieved_docs[0].metadata)
```

### 검색 파라미터 제어

- search_kwargs : 검색 실행 시 전달할 세부 옵션을 딕셔너리 형태로 지정
- k (Top-k) : 유사도 점수가 가장 높은 상위 문서의 반환 개수 제한

```python
# 상위 1개의 문서만 정확히 추출하도록 파라미터(k=1)를 설정합니다
custom_retriever = vector_store.as_retriever(
    search_kwargs={"k": 1}
)

# 장학금 관련 질문으로 검색을 수행합니다.
scholarship_query = "장학금을 받기 위한 직전 학기 평점 기준이 어떻게 되나요?"
custom_results = custom_retriever.invoke(scholarship_query)

# k값 설정에 따라 반환된 결과를 확인합니다.
print(f"반환된 문서 개수: {len(custom_results)}건")
for idx, doc in enumerate(custom_results, 1):
    print(f"[{idx}번 문서] {doc.page_content}")
```

### Retriever & LLM 모델 연동 검증

- Retriever가 찾은 문서를 참고 문맥으로 전달하고, LLM이 이를 바탕으로 답변을 생성한다.

### 체인 구성 & 최종 질의응답

- 문서 포맷팅 : 검색된 Document 리스트의 page_content를 줄바꿈 문자로 병합
- LCEL 파이프라인 : Retriever -> Format -> Prompt -> gpt -> StrOutputParser 순으로 데이터 전달

```python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

model = init_chat_model(
    model_provider="openai",
    model="gpt-5-mini",
    reasoning_effort="low"   # 추론 강도 낮게 → 빠르고 저렴
)

prompt = ChatPromptTemplate.from_messages([
    ("system", (
        "당신은 대학 학사 규정 안내 도우미입니다.\n"
        "제공된 [참고 문서]에만 근거하여 답변하고, 문서에 없는 내용은 지어내지 마세요.\n\n"
        "[참고 문서]:\n{context}"
    )),
    ("user", "{question}")
])

# 검색된 문서 리스트를 문자열로 결합하는 함수를 정의합니다.
def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

# Top-1 설정이 적용된 Retriever와 LLM 모델을 LCEL 파이프라인으로 결합합니다.
rag_chain = (
    {"context": custom_retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)

final_response = rag_chain.invoke("도서관 대출 권수와 기간 규정을 알려줘.")

print("=== [생성 답변] ===")
print(final_response)
```

## 3-2 벡터 검색과 거리 점수 분석

### 벡터 검색 실행 & 유사도 점수 추출

- 질문에 대한 검색 결과를 거리 점수와 함께 확인한다.

### 문서와 거리 점수 조회

- `similarity_search()`는 `Document` 목록을 반환한다.
- `similarity_search_with_score()`는 `(Document, score)` 튜플 목록을 반환한다. 이 실습의 코사인 거리 설정에서는 점수가 낮을수록 유사하다.

```python
# 사용자 질문을 정의합니다.
query_text = "도서관 책 대출 규정이 어떻게 되나요?"

# 유사도 점수를 포함하여 상위 3개의 문서를 검색합니다.
results_with_scores = vector_store.similarity_search_with_score(
    query=query_text,
    k=3
)
print(results_with_scores)
# 검색된 결과와 점수를 차례대로 출력합니다.
print(f"질문: {query_text}\n")
for rank, (doc, score) in enumerate(results_with_scores, 1):
    print(f"[{rank}순위 문서]")
    print(f"- 유사도 점수: {score:.4f}")
    print(f"- 문서 내용: {doc.page_content}")
    print(f"- 메타데이터: {doc.metadata}")
    print("-" * 50)
```

### 유사도 점수 해석과 거리 지표의 원리

### 코사인 거리

- 코사인 유사도 (Cosine Similarity)
  - 두 벡터의 방향이 완벽히 일치하면 1, 직교하면 0, 정반대면 -1
- 코사인 거리 ( Cosine Distance )
  - 데이터베이스에서는 '거리' 개념을 위해 1 - 코사인 유사도 공식 사용
- 수치 판별 기준
  - 코사인 거리는 0에 가까울수록 질문과 매우 유사함을 의미, 숫자가 커질수록 관련성이 떨어짐

| **지표 구분**                   | **계산 수식**      | **완벽 일치 시 값** | **완전 불일치 시 값** | **수치 해석 방법**         |
| ------------------------------- | ------------------ | ------------------- | --------------------- | -------------------------- |
| **코사인 유사도**               | $\cos(\theta)$     | `1.0`               | `0.0` 또는 `-1.0`     | **높을수록** 관련성이 높음 |
| **코사인 거리** (PGVector 기본) | $1 - \cos(\theta)$ | `0.0`               | `1.0` 이상            | **낮을수록** 관련성이 높음 |

### 검색 결과 디버깅 & 품질 분석

관련 문서가 있는 도서 대출 질의와 저장소 범위 밖인 식당 메뉴 질의의 검색 결과를 비교한다.

### 정상 질의 & 비정상 질의 점수 비교

```python
# 비교할 두 가지 질문 리스트를 정의합니다.
test_queries = [
    "도서 대출 가능 권수",              # 저장소에 존재하는 학사 규정 질문
    "캠퍼스 식당 오늘의 점심 메뉴 알려줘"   # 저장소에 없는 무관한 질문
]

for query in test_queries:
    print(f"\n[질의 분석 실행]: '{query}'")
    # 상위 2건의 문서와 점수를 검색합니다.
    search_results = vector_store.similarity_search_with_score(query=query, k=2)

    for rank, (doc, score) in enumerate(search_results, 1):
        print(f"  > {rank}위 (거리 점수: {score:.4f}) | 내용 요약: {doc.page_content[:40]}...")
```

### 검색 실패 시 점검 체크리스트

- 1순위 점수 과다 (거리 점수 0.6 이상) : 데이터베이스 내에 질문에 대응하는 지식 문서 자체가 누락된건지 확인
- 엉뚱한 문서 상위 노출 : 텍스트 청크가 너무 길어 여러 주제가 섞여 임베딩의 초점이 흐려졌는지 확인
- 동음이의어 왜곡 : 질문 문장의 특정 단어가 엉뚱한 문맥으로 임베딩되었는지 질문 문장 구조를 재점검

## 3-3 Top-k와 거리 임계값

- Top-k는 가까운 문서를 최대 몇 개까지 가져올지 정한다.

### Top-k 파라미터의 트레이드 오프

- k값이 과도하게 큰 경우 : 불필요한 정보가 포함되어 입력 토큰 비용이 증가하고 핵심 문맥이 흐려짐
- k가 과도하게 작은 경우 : 답변을 생성하는 데 필수적인 근거 문장이 누락되어 환각이 발생할 위험이 존재
- 적정값 설정 기준 : 일반적으로 단답형 질의 = 2~3 , 종합 분석형 질의 = 4~6 사이에서 테스트 진행

### Score Threshold 이용한 저품질 문서 제거

- 거리 임계값은 문맥에 포함할 문서의 최대 허용 거리를 정한다.

### 코사인 거리 기준 임계치 설정 원리

- PGVector는 코사인 거리(1 - 유사도)를 기본 지표로 사용하므로 수치가 작을수록 연관성이 높음
- 설정한 임계값보다 거리가 큰 문서는 제외한다. 다음 구간은 실습에서 사용한 판단 기준이다.

| **품질 구간** | **거리 점수 범위** | **판별 결과 및 조치** |
| --- | --- | --- |
| **우수 구간** | 0.00 ~ 0.35 | 질문과 핵심 의도가 일치하므로 문맥으로 주입 |
| **보통 구간** | 0.35 ~ 0.60 | 부분 관련성이 존재하므로 Top-k 조건에 맞춰 선별 사용 |
| **주의/탈락** | 0.60 초과 | 무관한 노이즈 문서로 판별하여 모델 입력에서 제외 |

## 3-4 메타데이터 필터링

- 문서마다 붙어 있는 속성 정보를 기준으로 검색 후보군을 사전에 압축하는 기술
  - 단순히 벡터 유사도에만 의존할 때 생기는 모호함을 없애고, 작성 일자나 담당 부서, 문서 카테고리 처럼 명확한 사실 조건을 충족하는 문서만 골라내어 검색 품질을 높임

### 유사도 검색의 한계와 메타데이터의 역할

- 의미 유사도의 한계
  - 벡터 검색은 의미적 유사성을 기반을 탐색하므로, 문장 구조가 유사한 경우 구 버전 문서를 오답으로 가져올 위험이 존재
- 메타데이터 조건을 걸면 해당 조건을 만족하는 문서로 검색 결과를 제한할 수 있다.

### PGVector의 메타데이터 문법 구조

- JSONB 기반 속성 보관 : PGVector는 문서의 부가 속성을 JSON 구조로 데이터베이스에 저장
- 단일 조건 문법 : filter={"category": "장학"} 형태로 특정 키와 값의 일치 여부 지정
- 다중 조건 문법 : filter={"category": "장학", "year": 2024} 형태로 여러 조건을 딕셔너리에 함께 나열

### 메타데이터 기반 벡터 검색

- 문서 본문과 메타데이터를 벡터 저장소에 함께 적재한 뒤, 특정 조건에 따라 필터링된 검색 결과를 직접 확인하고 검증

```python
# 본문 텍스트와 메타데이터 딕셔너리를 포함하는 Document 객체를 생성하여 데이터베이스에 저장

import os
from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_openai import OpenAIEmbeddings
from langchain_postgres.vectorstores import PGVector

load_dotenv()

embeddings_model = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# 데이터베이스 연결 주소를 확인합니다.
connection_url = os.getenv("DATABASE_URL")

# PGVector 벡터 저장소 컬렉션에 연결합니다.
vector_store = PGVector(
    embeddings=embeddings_model,
    collection_name="metadata_university_rules",
    connection=connection_url,
    use_jsonb=True
)

# 메타데이터가 포함된 규정 문서를 구성합니다.
sample_rules = [
    Document(
        page_content="[2024년 개정 장학 규정] 직전 학기 평점 3.8 이상 취득 시 전액 장학금을 지급합니다.",
        metadata={"category": "scholarship", "year": 2024, "target": "undergraduate"}
    ),
    Document(
        page_content="[2023년 구 장학 규정] 직전 학기 평점 3.5 이상 취득 시 전액 장학금을 지급합니다.",
        metadata={"category": "scholarship", "year": 2023, "target": "undergraduate"}
    ),
    Document(
        page_content="[2024년 도서관 규정] 학부생은 1인당 최대 7권까지 21일간 도서를 대출할 수 있습니다.",
        metadata={"category": "library", "year": 2024, "target": "undergraduate"}
    ),
    Document(
        page_content="[2024년 대학원 규정] 대학원생 연구 장학금은 지도교수 추천서를 필수로 제출해야 합니다.",
        metadata={"category": "scholarship", "year": 2024, "target": "graduate"}
    )
]

# 문서를 벡터 저장소에 추가합니다.
vector_store.add_documents(sample_rules)
print("메타데이터를 포함한 규정 문서 적재 완료")
```

```python
# 필터 유무에 따른 결과 비교
# 테스트 질의를 정의합니다.
query = "장학금 지원 기준을 알려줘"

# 메타데이터 필터 없이 유사도 검색(Top-k=2)을 실행합니다.
raw_results = vector_store.similarity_search(query=query, k=2)

print("=== [필터 미적용 검색 결과] ===")
for idx, doc in enumerate(raw_results, 1):
    print(f"[{idx}위 문서]")
    print(f" - 본문: {doc.page_content}")
    print(f" - 메타데이터: {doc.metadata}")

# 2024년도 장학금 규정만 선별하는 필터를 적용합니다.
target_filter = {
    "category": "scholarship",
    "year": 2024,
    "target": "undergraduate"
}

filtered_results = vector_store.similarity_search(
    query=query,
    k=2,
    filter=target_filter
)

print("\n=== [복합 메타데이터 필터 적용 검색 결과] ===")
for idx, doc in enumerate(filtered_results, 1):
    print(f"[{idx}위 문서]")
    print(f" - 본문: {doc.page_content}")
    print(f" - 메타데이터: {doc.metadata}")
```

## 3-5 검색 문맥을 주입하는 프롬프트 설계

### 검색 문맥 주입

- 검색된 참고 문서와 답변 지침을 함께 전달해 문서에 근거한 답변을 유도한다.

### 문맥 주입의 목적 & 환각 제어

- 외부 지식 강제
  - AI가 사전에 학습한 오래된 기억 대신, 프롬프트에 직접 입력된 최신 문서를 최우선 기준으로 채택
- 답변 범위 한정
  - "제시된 문서 내용 외에는 답변하지 말 것" 이라는 제약 조건을 부여하여 허위 정보 생성 방지

### RAG 프롬프트 템플릿 3요소

- 시스템 역할 & 지침 (System) : AI의 역할, 답변 어조, 참고 문서 외 임의 답변 금지 규칙 명시
- 참고 문맥 (Context) : 검색기를 통해 추출된 복수의 문서 본문이 들어가는 영역
- 사용자 질문 (Question): 사용자가 실제로 입력한 자연어 질문

```python
from langchain_core.documents import Document

retrieved_docs = [
    Document(
        page_content="[2024년 개정 장학 규정] 직전 학기 평점 3.8 이상 취득 시 전액 장학금을 지급합니다.",
```

```python
# 단순 결합 대신 문서 구분을 위한 번호와 줄바꿈 기호를 부여하여 가독성 높임
# 문서 리스트를 단일 문자열 문맥으로 변환하는 함수를 정의합니다.
def format_docs(docs: list[Document]) -> str:
    formatted_chunks = []
    # 각 문서 본문 앞에 번호를 붙여 정렬합니다.
    for index, doc in enumerate(docs, 1):
        formatted_chunks.append(f"[문서 {index}]\n{doc.page_content}")

    # 각 문서를 두 줄 띄움(줄바꿈 2회)으로 구분하여 결합합니다.
    return "\n\n".join(formatted_chunks)

# 포맷팅 함수를 실행하여 문맥 문자열을 생성합니다.
context_text = format_docs(retrieved_docs)
print("=== [포맷팅 완료된 문맥 문자열] ===")
print(context_text)
```
