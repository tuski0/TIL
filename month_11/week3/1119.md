## 7-1 평가셋 설계 원칙 적용

### 평가 목적과 골든셋
- 서비스 목적과 오답의 영향에 따라 평가 범위와 검증 강도를 정한다.
- 질문(Question), 모범 정답(Ground Truth / Answer), 근거 문서(Context)를 연결해 평가 기준을 만든다.
- 근거 문서는 검색 실패와 생성 실패를 구분하는 기준이 된다.
- 검색 지표와 생성 지표인 Faithfulness, Answer Relevance를 함께 검증할 수 있도록 설계한다.

### 질의 유형 커버리지
| 유형 | 확인할 내용 |
| --- | --- |
| 단순 사실 확인 | 문서에 명시된 사실을 정확히 찾고 답하는가 |
| 복합 추론 질문 | 여러 정보를 비교·종합할 수 있는가 |
| 문서 외 함정 질문 | 근거가 없는 질문에 임의로 답하지 않는가 |

### 실습 흐름
- 질의 유형, 질문, 정답, 근거 문서를 DataFrame으로 구성하고 CSV로 저장한다.
- LLM 검증 체인으로 질문의 유형과 판정 이유를 확인한다.

### 강의 예제 코드

```python
import pandas as pd

# 평가 데이터(골든셋)를 담을 리스트를 정의합니다.
# 유형, 질문, 정답, 근거 문서를 일대일로 매칭합니다.
eval_dataset = [
    {
        "query_type": "단순 사실 확인",
        "question": "도서관 주말 운영 시간과 대출 가능 권수는 어떻게 되나요?",
        "answer": "주말은 오전 10시부터 오후 5시까지 운영하며, 1인당 최대 5권까지 대출 가능합니다.",
        "context": "중앙도서관 운영 안내: 주말(토, 일)은 오전 10시부터 오후 5시까지 운영하며, 1인당 최대 5권까지 대출 가능합니다."
    },
    {
        "query_type": "문서 외 함정 질문",
        "question": "도서관 주말 대출 권수를 10권으로 늘리는 특별 신청 방법이 있나요?",
        "answer": "제공된 문서에는 대출 권수를 늘리는 별도의 신청 방법이 안내되어 있지 않습니다.",
        "context": "중앙도서관 운영 안내: 주말(토, 일)은 오전 10시부터 오후 5시까지 운영하며, 1인당 최대 5권까지 대출 가능합니다."
    }
]

# 파이썬 리스트 데이터를 2차원 표 구조의 DataFrame으로 변환합니다.
df_eval = pd.DataFrame(eval_dataset)

# 생성된 표 구조를 확인하고 파일로 내보냅니다.
print("=== [평가셋 설계 데이터프레임] ===")
print(df_eval[["query_type", "question"]])

# 추후 RAGAS 평가에 즉시 활용할 수 있도록 CSV 포맷으로 저장합니다.
df_eval.to_csv("rag_golden_set.csv", index=False, encoding="utf-8-sig")
```

```text
1  문서 외 함정 질문  도서관 주말 대출 권수를 10권으로 늘리는 특별 신청 방법이 있나요?
```

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser


load_dotenv()

# 일관성 있는 평가 판정을 위해 창의성 수치(temperature)를 0으로 고정합니다.
model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 평가셋 질문의 유형 적합성을 판별하는 프롬프트를 작성합니다.
type_check_prompt = PromptTemplate.from_template(
    "당신은 RAG 평가셋 품질 검수관입니다.\n"
    "[근거 문서]와 [질문]을 비교하여 해당 질문의 '질의 유형'을 아래 3가지 중 하나로 분류하고 판정 이유를 1줄로 작성하세요.\n\n"
    "1. 단순 사실 확인: 문서에 직접적인 정답이 명시되어 있는 경우\n"
    "2. 복합 추론 질문: 여러 문맥을 종합해야 정답 도출이 가능한 경우\n"
    "3. 문서 외 함정 질문: 문서 내용만으로는 정답을 알 수 없거나 문서에 없는 내용을 묻는 경우\n\n"
    "[근거 문서]: {context}\n"
    "[질문]: {question}\n\n"
    "[출력 형식]:\n"
    "판정 유형: <유형명>\n"
    "판정 이유: <1줄 사유>"
)

# 프롬프트, LLM, 문자열 파서를 파이프라인 체인으로 결합합니다.
validate_chain = type_check_prompt | model | StrOutputParser()

# 테스트할 평가 데이터셋 항목을 지정합니다.
sample_target = eval_dataset[1]

# 체인을 실행하여 LLM 모델의 자동 검증 결과를 확인합니다.
validation_result = validate_chain.invoke({
    "context": sample_target["context"],
    "question": sample_target["question"]
})

print("=== [질의 유형 검증 결과] ===")
print(validation_result)
```

```text
판정 이유: 문서에는 주말 대출이 최대 5권이라고만 명시되어 있고 10권으로 늘리는 특별 신청 방법에 대한 언급이 없어 문서만으로는 답을 알 수 없습니다.
```

## 7-2 평가셋 구축

### 데이터 스키마와 무결성 점검
- `query_type`, `question`, `answer`, `context`를 문항별로 연결한다.
- `pd.DataFrame()`으로 표를 구성하고 `isnull().sum()`으로 결측치를 확인한다.
- `assert`로 누락된 값이 있는지 점검한 뒤 품질 검수로 넘어간다.

### LLM 기반 자동 검수
- 근거 문서와 모범 정답을 함께 전달해 정답의 근거 일치 여부를 검토한다.

- 문항 유형의 다양성과 정답의 근거 일치 여부를 모두 확인한다.

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

# 채점 및 검수의 일관성을 유지하기 위해 temperature를 0으로 고정합니다.
model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 평가셋의 모범 정답이 근거 문서에 부합하는지 검수하는 프롬프트를 작성합니다.
quality_check_prompt = PromptTemplate.from_template(
    "당신은 RAG 평가셋 품질 검수관입니다.\n"
    "제공된 [근거 문서]를 바탕으로 [질문]과 [모범 정답]의 정합성을 검수하세요.\n\n"
    "[검수 기준]\n"
    "1. 일치: 모범 정답이 근거 문서의 사실에 완벽히 부합하거나, 정보가 없는 경우 적절히 문서 부재를 명시한 경우\n"
    "2. 불일치: 모범 정답이 근거 문서의 사실과 다르거나 근거 없는 내용을 단정한 경우\n\n"
    "[근거 문서]: {context}\n"
    "[질문]: {question}\n"
    "[모범 정답]: {answer}\n\n"
    "[출력 형식]:\n"
    "판정 결과: <일치 또는 불일치>\n"
    "검수 의견: <1줄 설명>"
)

# 프롬프트, 모델, 파서를 결합하여 검수 파이프라인 체인을 구성합니다.
quality_chain = quality_check_prompt | model | StrOutputParser()
```

```python
# 평가셋의 각 문항을 순회하며 gpt-5-mini 모델로 품질을 검수합니다.
inspection_results = []

for index, row in df_eval.iterrows():
    # 체인을 호출하여 검수 결과를 도출합니다.
    result = quality_chain.invoke({
        "context": row["context"],
        "question": row["question"],
        "answer": row["answer"]
    })
    inspection_results.append(result)

# 검수 결과를 데이터프레임의 새로운 열로 추가합니다.
df_eval["inspection_result"] = inspection_results

# 검수 결과 요약을 출력합니다.
print("=== [평가셋 자동 검수 완료 리포트] ===")
for i, res in enumerate(df_eval["inspection_result"]):
    print(f"[문항 {i+1}]\n{res}\n")

# 검수가 완료된 최종 평가셋을 CSV 파일로 저장합니다.
output_file = "rag_golden_set.csv"
df_eval.to_csv(output_file, index=False, encoding="utf-8-sig")
print(f"최종 저장 완료: '{output_file}' 파일이 생성되었습니다.")
```

## 7-3 RAGAS 검색 지표 측정

### 검색 품질 평가
| 지표 | 측정 대상 | 점검할 문제 |
| --- | --- | --- |
| Context Precision | 관련 근거가 검색 결과의 상위에 배치되는 정도 | 노이즈 문서, 관련 문서의 낮은 순위 |
| Context Recall | 모범 정답에 필요한 근거가 검색 결과에 포함된 정도 | 핵심 근거 누락 |

### 데이터와 평가 실행
- 질문은 `user_input`, 모범 정답은 `reference`, 검색 문서 목록은 `retrieved_contexts`에 담는다.
- DataFrame을 Dataset으로 변환하고 심사위원 LLM과 임베딩 모델을 래퍼로 연결한다.
- `evaluate()`에 검색 지표를 전달해 질문별 점수를 계산한다.
- `to_pandas()`로 결과를 확인하고 `search_eval_report.csv`로 저장한다.

### 강의 코드 확인 메모
- 아래 코드는 원문 예제를 보존했다. 심사위원 초기화는 `gpt-4o-mini`인데 진행 메시지 일부에는 `gpt-5-mini`가 적혀 있다.

## 7-4 RAGAS 생성 지표 측정

### 생성 품질 평가
| 지표 | 측정 방식 | 낮은 점수의 의미 |
| --- | --- | --- |
| Faithfulness | 답변을 진술로 나누고 참고 문서의 뒷받침 여부를 확인 | 사실 왜곡 또는 근거 없는 내용 |
| Answer Relevance | 답변에서 질문을 역생성하고 원래 질문과의 의미 유사도를 비교 | 질문 의도에서 벗어난 답변 |

### 실습 흐름
- 질문, 실제 답변, 검색 문맥을 평가 데이터로 구성한다.
- 심사위원 모델과 임베딩 모델을 연결하고 생성 지표를 측정한다.
- 질문별 지표를 비교해 사실성 저하와 관련성 저하를 구분하고 결과를 CSV로 저장한다.
- 문서 내용과 일치하는 답변도 질문에 필요한 정보를 제공하는지 함께 확인한다.

## 7-5 검색 실패 분석

### 검색 실패의 원인과 개선
| 원인 | 관찰할 증상 | 개선 방향 |
| --- | --- | --- |
| 청킹 실패 | 문장·표의 의미가 여러 청크로 끊김 | Chunk Size와 Chunk Overlap 조정 |
| 임베딩·어휘 불일치 | 정답 문서가 존재하지만 Top-k에서 누락 | 도메인 임베딩, BM25와 Hybrid Search 검토 |
| 메타데이터 필터링 실패 | 과거 연도나 다른 조건의 문서가 반환 | 색인 메타데이터와 필수 필터 점검 |

### 실습 흐름
- 검색 오류가 포함된 사례를 `EvaluationDataset`으로 구성한다.
- `LLMContextPrecisionWithReference`, `LLMContextRecall` 객체에 평가 모델을 연결한다.
- 검색 점수가 낮은 사례를 추려 질문, 정답, 검색 문맥을 진단 체인에 전달한다.
- 진단 내용에서 실패 원인과 수정 대상을 확인한다.

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_openai import OpenAIEmbeddings
from ragas import evaluate
from ragas.metrics import LLMContextPrecisionWithReference, LLMContextRecall
from ragas.llms import LangchainLLMWrapper
from ragas.embeddings import LangchainEmbeddingsWrapper

load_dotenv()

# 일관되고 객관적인 채점을 위해 temperature=0으로 고정한 gpt-4o-mini 모델을 선언합니다.
judge_model = init_chat_model(
    model="gpt-4o-mini",
    model_provider="openai",
    temperature=0
)

# 문장 임베딩 유사도 계산을 위한 모델을 선언합니다.
embedding_model = OpenAIEmbeddings(model="text-embedding-3-small")

# RAGAS 프레임워크가 인식할 수 있도록 래퍼 클래스로 감쌉니다.
evaluator_llm = LangchainLLMWrapper(judge_model)
evaluator_embeddings = LangchainEmbeddingsWrapper(embedding_model)

# RAGAS 클래스 기반 검색 지표 인스턴스를 선언하고 평가 모델을 전달합니다.
metrics = [
    LLMContextPrecisionWithReference(llm=evaluator_llm),
    LLMContextRecall(llm=evaluator_llm)
]

print("검색 평가를 실행합니다. gpt-4o-mini 모델이 정밀도와 재현율을 채점 중입니다...")

# evaluate 함수를 호출하여 검색 지표 측정을 진행합니다.
evaluation_result = evaluate(
    dataset=ragas_dataset,
    metrics=metrics,
    raise_exceptions=True
)

print("검색 지표 측정이 완료되었습니다.")
```

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 평가 결과를 데이터프레임으로 변환합니다.
df_result = evaluation_result.to_pandas()

# 평가 지표 컬럼명을 확인하고 매핑합니다.
precision_col = [c for c in df_result.columns if "context_precision" in c][0]
recall_col = [c for c in df_result.columns if "context_recall" in c][0]

# 정밀도 또는 재현율이 0.8 미만인 실패 사례만 선별합니다.
failed_cases = df_result[(df_result[precision_col] < 0.8) | (df_result[recall_col] < 0.8)].copy()
print(f"총 {len(df_result)}건 중 {len(failed_cases)}건의 검색 실패 사례가 식별되었습니다.")

# 검색 실패 원인을 청킹, 임베딩, 메타데이터 필터링 관점에서 분석하는 프롬프트를 구성합니다.
diagnosis_prompt = ChatPromptTemplate.from_template(
    """당신은 RAG 검색 파이프라인의 품질 문제를 진단하는 수석 엔지니어입니다.
아래의 질문, 모범 정답, 그리고 실제 검색된 문서를 대조하여 검색 실패 원인을 분석하세요.

[질문]: {question}
[모범 정답]: {reference}
[검색된 문서]: {contexts}

다음 3가지 항목에 맞춰 간결하고 담백하게 한국어로 작성하세요:
1. 실패 유형: [청킹 실패 / 임베딩 실패 / 메타데이터 필터링 실패 중 택1]
2. 상세 원인: [실패 이유를 2줄 이내로 명확하게 서술]
3. 파이프라인 개선안: [해결을 위한 파라미터나 구조적 조치 사항 1줄 요약]"""
)

# 원인 진단 체인을 구성합니다.
diagnosis_chain = diagnosis_prompt | judge_model | StrOutputParser()

# 실패 사례에 대해 순차적으로 원인을 진단합니다.
diagnosis_results = []
for _, row in failed_cases.iterrows():
    report = diagnosis_chain.invoke({
        "question": row["user_input"],
        "reference": row["reference"],
        "contexts": "\n".join(row["retrieved_contexts"])
    })
    diagnosis_results.append(report)

# 분석 결과를 데이터프레임에 반영합니다.
failed_cases["diagnosis_report"] = diagnosis_results

# 분석 결과 콘솔 출력
print("\n=== [검색 실패 원인 진단 결과] ===")
for idx, text in enumerate(failed_cases["diagnosis_report"]):
    print(f"\n--- [사례 {idx + 1}] ---\n{text}")

# 최종 리포트를 CSV 파일로 저장합니다.
output_csv = "search_failure_analysis_report.csv"
failed_cases.to_csv(output_csv, index=False, encoding="utf-8-sig")
print(f"\n검색 실패 분석 리포트가 성공적으로 저장되었습니다: '{output_csv}'")
```

## 7-6 생성 실패·환각 분석

### 생성 실패와 환각의 원인
| 원인 | 관찰할 증상 | 개선 방향 |
| --- | --- | --- |
| 환각 | 문서에 없는 인물·수치·정책을 생성 | 제공된 문서에만 근거하도록 지시 |
| 문맥 무시 | 정답이 문서에 있는데 반영하지 못함 | 문맥 압축, 핵심 정보와 질문의 배치 조정 |
| 프롬프트 지시 불이행 | 분량·출력 형식·언어 지침을 위반 | 지시사항 구조화와 Few-shot 예시 제공 |

### LLM 심사위원을 이용한 진단
- 질문, 참고 문서, 모범 정답, 생성 답변을 함께 비교한다.
- 판정 결과, 상세 원인, 프롬프트·컨텍스트 개선안을 출력하도록 템플릿을 구성한다.
- 의도적 오류 사례와 정상 사례를 모두 포함해 진단한다.
- 사례별 결과를 `diagnosis_report` 열에 추가하고 `generation_failure_analysis_report.csv`로 저장한다.

### 원문 예시 해석
- 강의 데이터에서는 연체료 오류를 문맥 무시 사례로 소개하지만, 예시 진단 출력은 환각으로 분류한다.
- 분류명과 함께 참고 문서의 어떤 사실을 어겼는지 확인한다.

```python
    print(report)

# 분석 결과를 데이터프레임의 새로운 컬럼으로 등록합니다.
df_generation_eval["diagnosis_report"] = diagnosis_reports

# 최종 리포트를 CSV 파일로 저장합니다.
output_csv = "generation_failure_analysis_report.csv"
df_generation_eval.to_csv(output_csv, index=False, encoding="utf-8-sig")

print(f"생성 실패 분석 리포트가 성공적으로 저장되었습니다: '{output_csv}'")
```
